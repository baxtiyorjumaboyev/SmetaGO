# SmetaGo — xavfsizlik va dizayn auditi (2026-09-29)

Metodika: [cloudflare/security-audit-skill](https://github.com/cloudflare/security-audit-skill) — har topilma aniq ishonch
chegarasi (kim → nima → qaysi resurs → natija) bilan, dalil manba kodi va **mahalliy** sinovdan; jonli saytga
hujum/yuklama berilmagan. Jiddiylik faqat isbotlangan oqibatga beriladi. Skillning validator skriptlari (Node.js)
ishlatilmadi — muhitda Node yo'q. Skill odatda faqat hisobot beradi; bu yerda foydalanuvchi so'roviga ko'ra tuzatildi.

Qamrov: autentifikatsiya (login, ro'yxat, parol tiklash, Telegram), obyektga egalik, API (state, Excel), brauzer
(XSS, service worker, localStorage), resurs sarfi, joylashtirish sozlamalari; dizayn — 13 sahifa × (kompyuter,
tungi rejim, telefon). Bu bitta o'tish — "qolgani xavfsiz" degani emas.

## Tekshirildi — muammo topilmadi

- Obyektga egalik: barcha `obyekt_*` view'lar `owner=request.user` bilan (begona obyekt — 404); o'zgartiruvchilar POST/PUT + CSRF.
- XSS: foydalanuvchi matni `innerHTML` ga faqat `esc()` orqali; Excel ko'rinishi ham `esc`; shablonlarda `|safe` faqat server JSON'ida; `json_script`, `escapejs` to'g'ri.
- Excel formula injection: `=` matni `data_type="s"`.
- Parol tiklash: Django tokeni (bir martalik, 24 soat), domen `ALLOWED_HOSTS` bilan cheklangan; noma'lum email — bir xil javob.
- `check --deploy` (server sozlamalari bilan): HSTS qo'shildi (1 yil, subdomensiz); SSL yo'naltirishni Caddy qiladi.

## Qattiqlashtirish tavsiyalari (topilma emas — keyingi ishlar)

- Login/admin uchun urinishlar chegarasi (brute force) — hozir yo'q; Caddy yoki `django-axes` bilan.
- Content-Security-Policy — shablonlardagi inline skriptlar nonce'ga o'tkazilgach.
- Server: SSH'da parol bilan kirish yoqilgan va parol suhbatda ochiq yozilgan — **parolni almashtiring**, faqat kalit bilan kirishni qoldiring.
- `db.sqlite3` zaxirasi avtomatlashtirilmagan (yangilashdan oldin qo'lda olinadi).
- Foydalanuvchi obyektlari soni cheklanmagan (har holat ≤ 2,5 MB) — kerak bo'lsa limit.
